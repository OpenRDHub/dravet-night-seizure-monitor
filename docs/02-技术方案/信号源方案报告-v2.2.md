---

## 结论

1. **主通道为非接触毫米波雷达**：呼吸、心率、体动、在床状态，儿童侧不依赖任何穿戴设备。
2. **手环作为第二条输入通道**：三轴体动（阵挛确认）与心率（第二来源）；戴家长手腕时提供震动提示。
3. **麦克风作为第三条输入通道**：声音事件，只参与升级判定，不单独报警。
4. **全系统只有一条规则层**。移除手环后，心率与呼吸由雷达单独承担，系统仍完整运行。
5. **监测目标限定为惊厥性发作**（强直阵挛、阵挛、强直）。依据：医生访谈明确「设备应重点针对惊厥性发作，非惊厥性或非动作性的发作很难通过穿戴设备记录到有效指标变化」；非惊厥性发作按需求方口径仅记录、不报警。
6. **报告中的报警阈值全部来自医生访谈的口径**，不再使用自定数值。

### 报警阈值（医生访谈）

| 指标 | 阈值 | 说明 |
| --- | --- | --- |
| 心率 · 大发作 | 比基线**增高 30–60 次/分，持续 >45 秒** | 45 秒为医生经验值，后续随数据积累调整 |
| 心率 · 持续异常 | 持续异常（如**持续低于 60 次/分**），异常持续 **5–10 秒**触发 | 与上一条相互独立 |
| 呼吸 | 发作期呼吸暂停 **10–30 秒** | ⚠️ 家长参会感受中的口径为「常规发作憋气通常持续 30–60 秒」，两处不一致，需向医生确认 |
| 血氧 | 发作后 **50–60 秒**才下降，有延迟但「准确率非常高」 | 定位为**报警升级**判据，不是初判据 |
| 体动 | 阵挛抽动间隔 **1–3 秒 或 1–5 秒**，初期快、临近结束变慢 | 与「翻身、睡眠抖动」的区别在于周期性与持续性 |
| 长时发作 | 持续 **超过 2 分钟**必须提醒家长 | 防致死性风险 |
| 发作后 | 单次发作结束后保持 **5–10 分钟**高风险监测 | 重点防呼吸心跳骤停与发作后呼吸抑制 |

## 通道划分

| 通道 | 位置 | 输出 | 角色 | 可独立报警 |
| --- | --- | --- | --- | --- |
| 毫米波雷达 | 床头（0.5–1.2 m，朝胸口） | 呼吸、心率、体动、在床状态 | 主通道：**呼吸是唯一来源**，同时提供心率与体动 | 是 |
| 手环（加速度计） | 儿童手腕（自愿佩戴） | 三轴体动 | 阵挛节律确认 | 否，与心率共同升级 |
| 手环（心率） | 儿童手腕（自愿佩戴） | 心率 | 心率的贴身第二来源，抗遮挡 | 否，与雷达交叉校验 |
| 手环（震动） | 家长手腕 | — | 分级提示输出 | — |
| 麦克风 | 床头 | 声音事件 | 补遮挡盲区与喉部声音 | 否，只参与升级 |

雷达不可替代的三个理由：

1. **呼吸是刚需，而唯一能非接触采集呼吸的就是雷达。** 医生把呼吸列为三项重点指标之一，家长原话说"呼吸监测功能是刚需"，同时明确不愿意为呼吸去戴胸带。
2. **猝死序列是"呼吸先停、心率后降"**，雷达同源同步采集呼吸与心率，能识别这个先后关系；腕部设备给不出呼吸这一路。
3. **"避免频繁脱落"是需求书明写的要求**。非接触设备不存在脱落问题，腕部设备在儿童身上被摘、被压、松脱是常态。

## 雷达使用条件与实施清单

### 安装与运行条件

| 项目 | 要求 | 依据与备注 |
| --- | --- | --- |
| 安装位置 | 床头或床边，略高于床面，朝胸口方向倾斜 | 呼吸信号来自胸廓毫米级起伏，波束必须覆盖躯干 |
| 安装距离 | 目标距离 0.5–1.2 m 为建议区间；海凌科 LD6002H 官方标称探测 0.8–1.5 m | MR60BHA2 的探测范围以 Seeed 官方 wiki 为准（官网国内访问不通，可查其 GitHub 文档镜像）——**待确认** |
| 视场与朝向 | 目标尽量落在波束中心；避免正对会动的物体（窗帘、风扇、宠物） | 移动物体会被当作体动目标 |
| 固定方式 | 雷达本体必须稳固，不能随床或人体晃动 | 本体晃动会引入伪信号 |
| 覆盖物 | 棉被、羽绒被、化纤被可穿透，衰减随厚度增加；**含金属纤维的被子（遮光被、防静电被）会几乎全反射** | 工程判断，需实测确认 |
| 床体 | 金属床架、金属床头板会产生强反射与多径干扰 | 建议调整角度或拉开距离 |
| 人数 | 单目标最佳；双人同床时两个目标互相干扰 | 本案演示场景为分房单人睡眠，不受此影响；同床与同房列为后续工作 |
| 气流 | 避免空调、风扇直吹被面 | 被面气流微动会被误判为体动 |
| 供电 | 需常供电（适配器或充电宝） | 整夜连续采集 |
| 数据链路 | 本地串口／BLE 直连接收端，不需要云、不需要外网 | 夜间断网不影响运行 |
| 接收端 | 需一台常开设备（笔记本电脑、树莓派或 ESP32） | 演示时用笔记本电脑即可 |

### 需要完成的工作

**硬件（下单优先，国庆物流 10/1–10/4 中断）**

1. 采购 MR60BHA2 套件（¥132–142，斑梨电子现货），另购一颗 LD6002H 作备份（约 ¥100）
2. 准备固定件：床头夹或支架、魔术贴、电源延长线
3. 确认演示场地是否有可用的床或床垫（赛事现场提供帐篷，不保证有床）

**软件（国庆假期内完成，这是唯一的整块时间）**

4. 最小读数程序：串口读数据 → 统一成 1 Hz 数据行 → 网页端画三条曲线（呼吸、心率、体动）
5. 数据活性检测层：连续无数据、数值恒定、目标消失三种情况都标记为「数据可疑」
6. 接入统一数据接口（`seq, t_recv, hr_radar, …`），为后续接入手环与麦克风留好位置

**实测（半天到一天，必须做）**

7. **距离梯度**：0.5／1.0／1.5 m 各测一次，看呼吸率输出是否稳定，据此确定最终摆位
8. **覆盖物对照**：薄毯与厚棉被各测一次，确认呼吸率是否仍可用
9. **憋气验收**：受试者憋气或故意打乱呼吸 20 秒，呼吸波形必须明显偏离
10. **体动节律测试**：模拟阵挛（约 1–3 秒一次的节律抖动），看体动输出能否分辨出节律，据此决定阵挛判据由雷达还是手环主责
11. **空床对照**：无人时确认雷达不会输出「有人」或持续体动
12. 每次实测留存原始数据文件与一页结论，作为答辩时可展示的验证记录

**现场（10/15 前确认）**

13. 确认演示床位的尺寸与位置，提前量好雷达安装距离
14. 准备备用线材、备用模块、胶带与固定件
15. 到场后先做一次现场标定（环境变化后距离与角度需重调），再进行五幕彩排

## 心率的双源处理

医生给出的两条心率判据都是本方案的核心触发条件，因此设两条来源：

| 来源 | 优势 | 劣势 |
| --- | --- | --- |
| 雷达 | 整夜连续、不依赖佩戴 | 受距离、被子厚度与遮挡影响 |
| 手环 | 贴身，抗遮挡 | 依赖佩戴；儿童夜间可能摘除 |

判定规则：

1. 未佩戴手环时，心率取自雷达。
2. 佩戴手环时，心率以手环为主源，雷达为交叉校验。
3. 两路心率差异超过设定阈值时，标记该时段心率不可靠，仅以呼吸与体动参与判定，并降级为记录。
4. 心率一律作为趋势与变化使用，不追求绝对值精度——医生判据是"比基线增高 30–60 次/分"的大幅跃升，不需要精细精度。

## 融合规则

**触发判据（阈值取自医生访谈）**

1. 心率比基线增高 ≥30 次/分且持续 >45 秒 → 报警（大发作判据）。
2. 呼吸暂停持续 ≥10 秒 → 报警或升级（对应 10–30 秒区间）。
3. 心率持续异常（如持续低于 60 次/分）达 5–10 秒 → 报警。

**升级判据**

4. 阵挛节律（间隔 1–3 秒或 1–5 秒）与心率骤升同时出现 → 二级预警。
5. 血氧下降（家庭测量录入）→ 报警升级。血氧在发作后 50–60 秒才变化，定位为升级判据。

**时序判据**

6. 事件持续 >2 分钟 → 强制提醒。
7. 事件结束后进入 5–10 分钟高风险监测期，重点监测呼吸抑制与心跳呼吸骤停；此期间若出现"呼吸停止在前、心率下降在后"的序列，按最高等级处理。

**基线与自学习**

8. 所有阈值相对「该患儿无发作夜间的平均心率」等个体化基线，不使用固定绝对值。
9. 氯巴占等镇静类药物调整后，重新采集基线（调药重校准）。
10. 家长一键标记误报 → 回写基线，同类特征下次降权。

**排除与可信度**

11. 必须排除：翻身、正常睡眠抖动、做梦肢体活动。
12. 任一路数据被判定为不可信 → 该时段只记录、不升级，并在夜报告中显式标出。

**统一数据接口**（每通道 1 Hz，三路共用同一时间基准）

```
seq, t_recv, hr_radar, hr_band, br, motion, sound, on_bed, quality
10231, 00:00:01.000, 78, 80, 18, 0.02, 0.11, 1, ok
```

`t_recv` 由接收端统一打戳，`seq` 用于识别丢包。任一通道不可用时留空，不得插值伪造；数据缺口带起止时间戳单独落库。

## 能力边界（写入方案正文）

**适用范围**

- 本方案针对**惊厥性发作**（强直阵挛、阵挛、强直）及其伴随的呼吸、心率异常。
- 非惊厥性发作（肌阵挛、失神等）不设报警，仅作为事件记录，用于完善癫痫日记。依据：产品需求书 5.3 与医生访谈一致。

**不自动采集的项目**

- **血氧**：非接触条件下原理上不可得；且血氧在发作后 50–60 秒才下降，不在抢时间的路径上。定位为报警升级判据，由家长在收到提示后测量录入。
- **体温**：非接触条件下不可得。定位为发热模式的触发条件，由家长标记（产品需求书 3.6 已列为后续迭代）。

**归入记录项、不作为报警项的内容**

- 面部与眼部微小抽动（口角、眼皮、眼眉）：该量级位移为亚毫米级，成品雷达模块只输出体动强度索引、不开放原始相位数据；腕部加速度计在手臂不动时读数接近零。按需求方口径，这类表现归入记录项，不触发夜间报警。
- 手指类细微肌阵挛：可由腕部加速度计捕捉，作为记录，同样不单独报警。

**精度声明**

- 非接触通道的心率与呼吸率**以趋势与大幅变化为判据，不承诺绝对值精度**。医生给出的心率判据是「比基线增高 30–60 次/分、持续 >45 秒」，属大幅跃升，不受几个 bpm 的误差影响。
- 本场景下的实测偏差由赛前对照标定得出（见《验证与标定》），结论仅在该场景条件（距离、覆盖物、体位）下成立，写入验证记录随方案提交。

**已知漏检场景**

- 短暂、且未引起心率或呼吸改变的发作存在漏检可能，方案中如实标注。
- 腕部设备在手臂被外部按住时整体漏报（EpiWatch 三期试验唯一漏掉的强直-阵挛发作即因此发生），这是手环通道的结构性限制。

## 软件约束与数据活性检测

| 约束 | 后果 | 本案处理 |
| --- | --- | --- |
| 采样率决定算法上限 | 25 Hz（奈奎斯特上限 12.5 Hz）无法做精细频谱判别，只能停在「频带能量 + 持续时间」这一层 | 手环只做阵挛确认；主判定走雷达的呼吸与心率 |
| 心率时间分辨率 | 每 5 秒一个心率点会把 45 秒尺度的变化趋势削弱 | 手环心率目标 ≥ 1 Hz 或逐拍 |
| 是否带时间戳 | 设备不带时间戳时时间轴会混入 BLE 抖动与整夜漂移 | 三路统一由接收端打戳并记录序列号 |
| 不提供佩戴有效性标志 | 协议层无法区分「戴着但静止」与「设备掉在床头柜上」 | 自建活性检测层 |
| 加速度计量程 | 若为 ±2G，抽搐峰值会饱和削顶 | 写判定代码前先确认量程 |
| 断连与数据缺口 | 实时流中断，事后无法补齐 | 缺口显式建模；「整夜无发作」的结论必须建立在「数据连续且有效」之上 |
| 部署形态 | 不需要云、不需要厂商 App 常驻 | 全本地 BLE + 本地判定 |

**数据活性检测（三路都要自建）**

绝不把「没有新数据／数值为零／数值恒定」判为「状态正常」：

1. 手环：监测重力矢量方向是否稳定（脱落时朝向会随机翻转）
2. 雷达：监测是否持续输出目标距离与相位（无目标 ≠ 状态正常）
3. 麦克风：监测环境本底噪声是否存在（长时间完全静默通常意味着采集中断）
4. 任一路不可信时，该时段标记为「数据可疑」，只记录不升级，并在夜报告显式标出

## 验证与标定

**赛前必做（半天到一天）**

1. 雷达单路跑通：呼吸、心率、体动三路数据在网页端实时显示。
2. 憋气验收：受试者躺卧，憋气或故意打乱呼吸 20 秒，呼吸曲线必须明显偏离。
3. **心率对照标定**：用 ECG 心率带与雷达同时采集，比较两条心率曲线。带式设备为心电级参考；若趋势一致，即取得「心电级设备验证非接触心率可用性」的技术证据。
4. 厚被对照：薄毯与厚棉被各测一次，比较呼吸率输出稳定性，据此确定建议距离。

**阻塞项（写判定代码之前必须确认）**

1. 手环加速度计的量程（±2G 会削顶）
2. 手环心率的输出频率（≥1 Hz）
3. 断连期间设备是否缓存补传
4. 雷达在 0.8–1.5 米、有覆盖物时的呼吸输出稳定性
5. 雷达体动输出的采样率能否支撑 1–5 秒间隔的节律判别（换算为 0.2–1 Hz），决定阵挛判据由雷达还是手环主责

**明确不做**

不在真实患儿身上做整夜参数扫描或临床验证（伦理、合规与赛期均不允许），相关验证列入赛后研究计划，方案中不承诺检出率。
