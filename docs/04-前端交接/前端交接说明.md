# 赛题 05 夜间监护系统 前端交接说明

版本：v1.0 ｜ 2026-10-02 ｜ 适用：罕见·无界黑客松 赛题 05（Dravet 夜间监护）

这份文档给负责前端页面的队友。看完应该能明确三件事：数据从哪来、数据长什么样、页面要做出什么效果。不需要懂雷达原理，也不需要懂医学。

---

## 一、这个系统在做什么

孩子夜里发作，家长不敢睡。设备放在床头，不接触孩子，整夜监测呼吸、心率、体动和声音。**发现可疑事件时，只提醒家长，不去打扰孩子**——孩子房间零声光，提示走家长手机的震动和提示音。

系统给出两类东西：一类是每秒变化的体征数值，画成曲线；另一类是被判定为"可疑事件"的记录，用来提醒家长、并沉淀成第二天早上给医生看的报告。

**判断是谁做的**：设备的判断逻辑不在前端。前端只负责"把数据画出来、把事件送到家长眼前"。

---

## 二、雷达怎么工作（够用就行）

床头一个小盒子，里面是 60GHz 毫米波雷达。它发出电磁波，打到人身上再反射回来。胸廓随呼吸起伏几毫米、心跳带来更小的体表位移、翻身是几十厘米的大位移——这些都会改变反射波的相位。模块从相位变化里算出三个数：呼吸率、心率、体动强度，通过串口一行行输出。

三条边界要知道：

1. **模块给的是体征数值，不是发作判断**：它输出"呼吸率 18"，不会输出"这是发作"。
2. **血氧和体温测不了**：这两个不在本系统的自动采集范围内。
3. **覆盖物和人数会影响信号**：厚被子会衰减，含金属纤维的被子基本挡死；双人同床会互相干扰。我们的演示场景是孩子单独一个房间，不存在这个问题。

---

## 三、数据从哪来

```
雷达模块（串口）
   ↓  后端读取、解析、合并双路心率、跑判定规则
接收端程序（我这边写）
   ↓  WebSocket，每秒推送
前端页面（你这边做）
```

前端**不接触雷达、不读串口、不做解析、不做判定**。你只需要连上 WebSocket，收两类消息：体征流和事件流。

---

## 四、数据接口

### 1. 体征流（每秒一条）

```json
{
  "seq": 10231,
  "t": "2026-10-15T22:13:05.000+08:00",
  "hr": 78,
  "br": 18.2,
  "motion": 0.02,
  "sound": 0.11,
  "on_bed": true,
  "quality": "ok"
}
```

| 字段 | 含义 | 单位／范围 | 前端怎么用 |
| --- | --- | --- | --- |
| seq | 序号 | 递增整数 | 用来发现丢包，跳跃即丢数据 |
| t | 时间戳 | ISO 8601，东八区 | 横轴时间基准 |
| hr | 心率（已合并双路来源） | bpm，取不到为 null | 一条曲线 |
| br | 呼吸率 | 次/分，一位小数 | 主曲线，视觉权重最高 |
| motion | 体动强度 | 0–1 归一化 | 柱状或填充区 |
| sound | 环境声音强度 | 0–1 归一化 | 折线或辅助层 |
| on_bed | 是否在床上 | true / false | 离床时曲线置灰 |
| quality | 数据可信度 | ok / stale / missing | 非 ok 必须显式提示 |

`hr` 在后端已经做过双源合并（雷达为主、手环校验），前端不关心来源；如果将来需要区分，会额外加一个 `hr_source` 字段。

### 2. 事件流（判定结果，随时可能推）

```json
{
  "event_id": "e-20261015-01",
  "t_start": "2026-10-15T23:41:02+08:00",
  "t_end": "2026-10-15T23:41:58+08:00",
  "level": 1,
  "title": "呼吸变慢，请抬头看一眼",
  "reasons": ["呼吸暂停 14 秒", "心率较基线 +12 次/分"],
  "suggest": "先看一眼孩子的呼吸和脸色，不用马上起身"
}
```

| 字段 | 含义 | 说明 |
| --- | --- | --- |
| event_id | 事件编号 | 唯一，用于去重和列表排序 |
| t_start / t_end | 起止时间 | 事件可能持续数十秒到几分钟，`t_end` 在事件结束时才出现，进行中为 null |
| level | 等级 | 1 = 一级（低打扰）；2 = 二级（需要起床） |
| title | 主提示语 | 直接显示，不要改写 |
| reasons | 触发原因 | 一行一条，展开显示 |
| suggest | 建议动作 | 直接显示 |

**一条重要约定**：事件是后端算好的，前端**不要反推、不要自己判断**。比如看到心率突然升高，前端不需要做任何逻辑，等后端推事件即可。

### 3. 数据质量与断流

`quality` 有三个值：`ok`（正常）、`stale`（数据陈旧）、`missing`（该通道缺失）。

- `quality != "ok"` 时：界面必须出现明确的"数据可疑"标记，不能静默继续画线
- 连续 **10 秒**没有收到新的体征数据：显示"数据中断"
- 整夜报告的"无异常"结论，只能建立在数据连续有效的前提上；有中断的时段要在报告里标出来

---

## 五、前端不做什么（三条边界，请守住）

1. **不做判定**：阈值、多路共振、持续时间全在后端。前端拿到什么画什么。
2. **不猜数据**：缺数据就显示缺数据，断流就显示断流，不允许用上一帧一直填充装作正常。
3. **不用诊断语言**：文案规范见第九节。

---

## 六、要做的三个页面

### 页面 1 · 家长端实时大屏（手机浏览器打开）

**目标**：家长半夜瞄一眼就知道现在什么情况，不用看完数据。

**元素**

- 三条曲线：呼吸（主，画粗）、心率、体动；滑动窗口 60 秒
- 顶部一行状态字，例如"整夜安静"
- 分级提示条：一级＝黄色横幅 + 一行大字 + 柔和提示音；二级＝红色全屏 + 持续强提示
- 数据可疑时右上角灰色角标

**验收**

- 60 秒滑动窗连续更新不卡顿
- 一级和二级在视觉与声音上能一眼区分
- 二级能真正把人叫醒（音量、持续时长要够）

### 页面 2 · 夜报告

**目标**：早上给家长看昨晚发生了什么，给医生看一页关键记录。

**元素**

- 整夜时间轴，异常事件打点
- 事件列表：时间、等级、持续时长、触发原因
- 一页"给医生的记录卡"，可打印、可导出
- 两个关键数字：整夜被打扰次数、家长连续睡眠 ≥4 小时的天数

**技术提醒**：整夜按 10 小时、每秒一条算，约 3.6 万个点。时间轴不要全量渲染，做降采样或分段加载。

**验收**

- 记录卡打印在一页 A4 内
- 数据中断的时段在时间轴上可见

### 页面 3 · 演示控制页（内部用，不对外）

**目标**：现场演示时的一键触发，防止真实表演失误。

**元素**：五个按钮，对应五幕

| 按钮 | 对应场景 | 期望结果 |
| --- | --- | --- |
| A | 平静睡眠 | 曲线平稳，无提示 |
| B | 翻身 | 体动跳一下，只记录不报警 |
| C | 呼吸异常 | 呼吸曲线明显偏离，一级提示 |
| D | 疑似惊厥 | 体动 + 声音 + 心率同时异常，二级提示 |
| E | 打开夜报告 | 跳到页面 2 |

## 七、技术约定

1. **先用模拟数据开发，不要等硬件**：我会给一份 30 分钟的假数据，含一次一级、一次二级事件。
2. **图表库不限**，能画 60 秒滑动窗就行（ECharts、Chart.js、纯 Canvas 都可以）。
3. **全本地运行**，不需要后端账号、不需要云服务。
4. **手机浏览器就够，不要做原生 App**（签名、安装、证书在赛场上是坑）。
5. 页面上不出现患儿姓名等隐私信息，设备名用"设备 A"这类代号。

## 八、判定阈值（只是让你理解界面为什么报警，不需要你实现）

这些数字在后端，列出来是为了让你理解提示的时机：

| 判据 | 阈值 |
| --- | --- |
| 心率升高 | 比基线高 30–60 次/分，且持续超过 45 秒 |
| 心率持续偏低 | 持续低于 60 次/分，达 5–10 秒 |
| 呼吸暂停 | 持续 10 秒以上 |
| 长时发作 | 事件超过 2 分钟，强制提醒 |
| 事件结束后 | 继续高风险监测 5–10 分钟 |

阈值都相对"这个孩子自己的夜间基线"，不是固定数字。所以界面上不需要展示阈值，只需要展示提示等级。

## 九、文案规范

| 不要用 | 换成 |
| --- | --- |
| 癫痫发作 | 疑似发作事件 |
| 确诊 / 判断为 | 检测到异常 |
| 病情严重 | 建议尽快查看 |
| 救命 / 危险 | 请立刻起身查看 |
| 检出率 100% | 不承诺检出率 |

界面上的所有文案以"让家长看懂、知道下一步做什么"为准，不用医学术语。

## 十、验收清单

1. 用模拟数据能把三条曲线跑起来，60 秒窗口滑动流畅
2. `quality` 不是 `ok` 时，界面明确显示"数据可疑"
3. 断流 10 秒内出现"数据中断"提示
4. 一级与二级提示在视觉和声音上可区分，二级能叫醒人
5. 给医生的记录卡在一页 A4 内
6. 演示控制页五个按钮都能触发对应场景
